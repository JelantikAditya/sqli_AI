## Pembaruan: embedding, Chroma, dan indexing PDF terverifikasi

Setup dilanjutkan setelah peneliti juga mengonfirmasi Qwen berjalan baik.
Virtual environment `.venv/` menggunakan Python 3.13. Paket utama yang
terpasang adalah Chroma 1.5.9, pypdf 6.19.0, dan fontTools 4.66.1;
`pip check` tidak menemukan dependensi rusak. Snapshot versi seluruh paket
disimpan di `outputs/rag-local-smoke/requirements-resolved.txt`.

Model `nomic-embed-text:latest` berhasil diunduh (274 MB, ID pendek
`0a109f422b47`). Smoke test `dvwa/smoke_rag.py` menghasilkan embedding 768
dimensi, menyimpan tiga dokumen sintetis, dan mengambil dokumen error-based
sebagai hasil pertama untuk query S1. Pengujian kedua dalam proses Python
baru memastikan index persisten tetap bisa dibaca. Fixture sintetis disimpan
terpisah dari korpus penelitian.

### Perbaikan yang diperlukan saat integrasi

- Pipeline lokal memakai `search_document:` untuk chunk dan `search_query:`
  untuk query Nomic, sesuai
  [petunjuk model](https://huggingface.co/nomic-ai/nomic-embed-text-v1.5#usage).
  Format ini tercatat di manifest dan fingerprint build. Manifest lama tanpa
  format tersebut tetap memakai query tanpa prefix agar cocok dengan index lama.
- `fontTools` ditambahkan karena pembacaan font CFF/Type1 pada beberapa PDF
  memunculkan peringatan encoding. Versi extractor dicatat pada konfigurasi build.
- Batas 220 kata tidak selalu membatasi jumlah token. Build sempat ditolak
  oleh Ollama karena context embedding terlampaui. Chunk sekarang juga dibatasi
  1.200 karakter dengan overlap; teks panjang dibagi, bukan dipangkas. API
  embedding memakai `truncate: false` agar input berlebih tidak terpotong diam-diam.
- Pemeriksaan chunk mencakup seluruh kata input normal, batas panjang potongan
  tanpa spasi, dan terpeliharanya bagian akhir teks. Dua index build yang tidak
  selesai dibersihkan setelah build akhir berhasil.
