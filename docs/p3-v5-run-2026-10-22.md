# Hasil eksekusi cohort P3 v5

Status: **berhenti pada unit pertama setelah kegagalan HTTP 500 dari provider**.
Run dimulai atas persetujuan peneliti, lalu berhenti otomatis ketika analisis
untuk S1-A gagal. Cohort tidak menghasilkan hasil P3 yang lengkap atau metrik
FPR/PSR.

| Properti | Hasil |
| --- | --- |
| Experiment ID | `qwen38-api-r4-20261022` |
| Protocol ID | `qwen38-api-sqli-v5-pilot` |
| Batas request API / waktu | 960 / 6 jam |
| Request API terpakai | 6 |
| Status API | 5 HTTP 200, 1 HTTP 500 |
| Stage API | 3 generasi, 3 analisis |
| Status slot | 0 completed, 1 invalid, 32 planned, 3 excluded |
| Request HTTP ke DVWA / reset database | 54 / 1 |
| Pemeriksaan API terpisah setelah run | 2 HTTP 200; satu terpotong, satu `API_OK` |

Kegagalan terjadi pada analisis ketiga, sesudah lima panggilan API sebelumnya
berhasil. Gateway mengembalikan HTTP 500 dengan `code=get_channel_failed` dan
pesan bahwa grup `auto` tidak memiliki channel tersedia untuk model
`Qwen3.8-27B`. Respons datang dalam 2,624 detik, sehingga ini bukan timeout.
Pesan tersebut sejalan dengan kegagalan routing yang tercatat di r3. Pengecekan
endpoint sebelumnya yang mendapat HTTP 200 membuktikan akses bekerja saat itu,
tetapi tidak memastikan channel model tersedia secara konsisten.

Runner tidak melakukan retry transport dan menandai S1-A invalid. Cohort r4
tidak dapat dilanjutkan dengan ID yang sama. Walaupun request generasi yang
tercatat berhasil, mekanisme retry duplikat v5 tidak terpicu pada run ini;
mekanisme tersebut baru divalidasi oleh tes offline. Ledger final tidak
mencatat kandidat valid yang dapat dipakai untuk evaluasi. Karena unit lain
belum dijalankan, jangan hitung hasil ini sebagai FPR/PSR atau gabungkan dengan
r3.

Sesudah runner berhenti, pemeriksaan diagnostik pertama mendapat HTTP 200 tetapi
terpotong karena batas 16 token terlalu kecil untuk reasoning. Saya mengulang
preflight dengan format yang sebelumnya berhasil, yaitu 128 token dan mode
non-thinking. Pemeriksaan kedua mendapat HTTP 200, model
`self-dploy/Qwen3.8-27B`, dan respons `API_OK` dalam 1,835 detik. Jadi route
Qwen merespons kembali pada saat pemeriksaan kedua. Dua pemeriksaan itu tidak
membuktikan kestabilan untuk analisis panjang. Masing-masing memakai satu
request API dan tidak mengirim request ke DVWA.

Tindak lanjut yang disarankan adalah memastikan dari sisi provider bahwa grup
`auto` memiliki channel aktif untuk alias `Qwen3.8-27B`. Setelah akses stabil,
siapkan ID, plan, dan budget cohort baru. Jika provider atau model diganti,
periksa ulang validasi adapter dan kesetaraan profil analisis sebelum cohort
berikutnya.
