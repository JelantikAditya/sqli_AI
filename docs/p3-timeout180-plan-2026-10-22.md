# Draft P3 plan dengan timeout analisis 180 detik

Draft `qwen38-api-r3-20261022` menyiapkan pengulangan cohort P3 dengan waktu tunggu transport analisis 180 detik. Perubahan hanya untuk analisis P3. Timeout generasi tetap 90 detik, sedangkan pengaturan P2 dan berkas konfigurasi dasarnya tetap tidak diubah.

## Perubahan yang disiapkan

Protokol pengembangan baru diberi ID `qwen38-api-sqli-v4-pilot`. Adapter P3 menggunakan opsi analisis yang sama dengan P2, yaitu endpoint, model, prompt, temperature, dan batas output 2.048 token. Timeout adalah batas lokal pada transport, bukan bagian dari payload API; tes offline membuktikan payload analisis tidak berubah ketika timeout transport menjadi 180 detik.

Client API saat ini menerima timeout sampai 180 detik. Runner v4 mengikat nilai timeout ke profile dan hash runtime, menyimpan profile pada snapshot, serta menolak resume atau overwrite pada ID eksperimen yang sama. Batas total tetap 960 request API dan enam jam. Enam jam adalah ceiling; timeout per request yang lebih panjang tidak menjamin cohort selesai dalam batas tersebut.

## Cakupan dan validasi

Plan mengulang **33 unit applicable** pada A/B/C, S1-S12, satu replikasi; tiga slot C/Impossible tetap excluded sesuai desain. Semua unit memakai satu ID dan profile yang sama, serta hasil run terdahulu tidak digabung.

Tiga tes offline lulus untuk memastikan timeout P2 tetap 90 detik, generasi tetap 90 detik, analisis P3 menjadi 180 detik, payload request tetap sama, dan deadline gate menyisakan waktu cukup sebelum memulai request. Dry-run bounded menghasilkan 36 slot dan batas worst-case 960 request dengan `execution_started: false`. Tidak ada request API, request DVWA, reset database, atau folder hasil run baru.

## Batas dan status keputusan

Timeout yang lebih panjang dapat menampung respons analisis yang lambat, tetapi tidak menjamin gateway selalu tersedia. Peneliti kemudian menyetujui satu cohort baru. Hasil aktual berhenti pada S7-B setelah API generasi mengembalikan HTTP 500. Tidak ada timeout transport pada 234 request yang tercatat. Sembilan unit LLM excluded karena kandidat valid tidak mencapai target 10; audit rinci menemukan saran `duplicate_structure` berulang. Rincian ada di [laporan run](p3-timeout180-run-2026-10-22.md) dan [audit eksekusi](evidence/p3-timeout180-execution-audit-2026-10-22.json).

Dokumen dan receipt persiapan tetap menjadi snapshot sebelum run. Cohort berhenti dengan 13 unit applicable belum dijalankan; tidak ada retry atau replacement, dan hasilnya bukan FPR/PSR formal. Runner menolak resume atau overwrite pada ID yang sama, sehingga pengujian lanjutan memerlukan ID, plan, dan budget baru.
