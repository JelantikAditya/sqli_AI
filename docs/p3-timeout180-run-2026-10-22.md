## Temuan utama

Tidak ada API request yang timeout pada cohort ini. Satu-satunya kegagalan
API adalah HTTP 500 pada panggilan generasi terakhir,
`00234-generation-b89a4223`, untuk S7-B. Respons itu menghasilkan nol kandidat
dan unit menjadi invalid. Runner tidak melakukan retry. `error_detail` dari
gateway menyatakan bahwa grup `auto` tidak memiliki channel tersedia untuk
model `Qwen3.8-27B` (`type=new_api_error`, `code=get_channel_failed`). Respons
diterima dalam 7,821 detik, tanpa `reported_model`, response ID, atau konten
generasi. Payload yang tercatat berisi dua pesan, `max_tokens=1024`, dan
`stream=false`. Dua call sebelumnya pada run yang sama, termasuk generasi
Qwen, sukses dengan HTTP 200. Bukti ini menunjuk ke kegagalan routing atau
ketersediaan channel di gateway, bukan timeout. Artefak klien tidak dapat
memastikan apakah channel sedang down, dinonaktifkan, kehabisan kuota, atau
tidak cocok dengan grup routing; diagnosis penyebab spesifik memerlukan log
gateway/provider.

Sembilan unit LLM lainnya excluded karena tidak mencapai anggaran minimum 10
kandidat valid. Unit tersebut menghasilkan 5 sampai 9 kandidat valid. Audit
generasi menunjukkan 30 saran ditolak sebagai `duplicate_structure` di
sembilan unit excluded. Satu saran tambahan dengan status yang sama terjadi
pada B-S4, tetapi unit itu tetap memenuhi target; totalnya 31 penolakan pada
10 unit. Ini berbeda dari kolom `duplicate_candidate_count`, yang tetap nol
untuk unit excluded karena saran tersebut ditolak sebelum menjadi kandidat
yang diterima.

## Kesimpulan dan tindak lanjut

Timeout analisis 180 detik cukup untuk menyelesaikan request analisis yang
tercatat, berbeda dari recovery sebelumnya yang berhenti pada read timeout.
Run ini mencatat satu kegagalan routing saat gateway tidak menemukan channel
tersedia untuk model pada grup `auto`; satu kejadian ini belum cukup untuk
menilai kestabilan provider secara umum. Kegagalan yang paling sering terlihat
adalah penolakan struktur payload saat generasi, bukan timeout analisis.

Sebelum cohort baru, tindak lanjut yang disarankan:

1. Audit kebijakan variasi dan deduplikasi kandidat agar loop menghasilkan 10
   kandidat struktural berbeda atau berhenti dengan alasan yang terukur.
2. Cocokkan trace ID pada error call 234 dengan log gateway/provider untuk
   memastikan mengapa grup `auto` tidak menemukan channel Qwen; setelah
   channel tersedia, lakukan preflight akses Qwen terpisah.
3. Buat plan dan budget baru. Runner tidak melanjutkan atau menimpa ID
   `qwen38-api-r3-20261022`.

Run ini masih memakai Qwen. Jika penelitian beralih ke Poolside Laguna, perlu
adapter, P2, pilot, dan cohort formal terpisah dengan identitas eksperimen
baru.
