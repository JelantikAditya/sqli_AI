# Hasil eksekusi cohort P3 v5 r5

Status: **berhenti pada S2-A akibat HTTP 500 saat generasi**. Run r5 dimulai
dengan ID baru setelah r4 invalid; hasil dua cohort tetap terpisah.

Kegagalan terjadi pada panggilan generasi ke-63 untuk A-S2, setelah 62 respons
HTTP 200. Gateway mengembalikan `get_channel_failed` dengan pesan bahwa grup
`auto` tidak memiliki channel tersedia untuk Qwen3.8-27B. Respons datang dalam
4,760 detik. Ini kegagalan routing provider, bukan timeout atau parser. Kelas
error yang sama muncul di r3 dan r4. Preflight singkat sebelum r5 memang
menghasilkan HTTP 200 dan `API_OK`, tetapi hasil itu tidak menjamin ketersediaan
channel sepanjang cohort.

Retry duplikat v5 teruji pada respons langsung model. Di A-S1, satu duplikat
ditolak dan retry menghasilkan kandidat berbeda, sehingga unit mencapai 10
kandidat valid. Di B-S2, slot 6 dan 7 berhasil setelah masing-masing menolak
duplikat. Slot 8 mengulang struktur duplikat pada ketiga percobaan dan unit
berhenti dengan 7 dari 10 kandidat valid; unit tersebut dikecualikan. Ini
menunjukkan retry memory bekerja sebagai pengecualian, tetapi belum cukup untuk
memastikan target 10 kandidat selalu tercapai.

Runner berhenti setelah S2-A invalid. Dari 33 unit applicable, empat selesai,
satu dikecualikan karena kandidat valid kurang dari target, satu invalid, dan
27 belum berjalan. Tiga slot C pada DVWA Impossible tetap excluded sesuai
desain. Cohort belum lengkap, jadi jangan hitung FPR/PSR atau gabungkan hasil
r5 dengan r4.

Rincian ada pada
`results/raw/pilot/qwen38-api-r5-20261022/` dan receipt
`docs/evidence/p3-v5-r5-execution-audit-2026-10-22.json`. Persetujuan eksekusi
dicatat pada `docs/evidence/p3-v5-r5-execution-approval-2026-10-22.json`.

Tindak lanjut yang disarankan: minta provider memastikan grup `auto` memiliki
channel aktif dan stabil untuk alias `Qwen3.8-27B`, atau pilih route/provider
lain. Jika model atau provider diganti, validasi adapter dan kesetaraan profil
P2 sebelum memulai cohort baru dengan ID segar.
