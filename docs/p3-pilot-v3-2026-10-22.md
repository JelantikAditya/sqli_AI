# Hasil pilot pemulihan P3 v3, 22 Oktober 2026

Pilot pengembangan `qwen38-api-p3-v3-pilot-20261022` berjalan selama 15 menit
15 detik dan berhenti pada request analisis S2-B yang mengalami timeout
transport 90,114 detik. Tidak ada retry atau attempt pengganti otomatis.
Batas 960 request dan gate enam jam tidak terlampaui.

## Status eksekusi

| Bagian | Hasil |
| --- | ---: |
| API request | 45 dari maksimum 960 |
| Respons HTTP 200 | 44 |
| Transport timeout tanpa status HTTP | 1 |
| Run LLM lengkap dan eligible | 1, B/S1 |
| Run SecLists lengkap dan eligible | 2, C/S1 dan C/S2 |
| Run A/S1 tidak lengkap | 8 kandidat dari 10, lalu tiga penolakan duplikat |
| Run B/S2 | Invalid saat analisis kandidat akibat timeout API |
| Applicable belum dimulai | 28 |
| Slot C/Impossible yang memang excluded | 3 |

Status ledger akhir adalah tiga completed, satu invalid, empat excluded dan
28 planned. Empat excluded mencakup tiga slot C/Impossible serta A/S1 yang
budget kandidatnya tidak lengkap. Run B/S2 melakukan reset database dan 72
request HTTP. Nilai logical probe untuk run invalid itu tidak tersedia, jadi
tidak dihitung sebagai nol.

Jumlah request API terdiri dari 24 generasi dan 21 analisis. Semua 44 respons
yang kembali memperoleh HTTP 200. Request ke-45, analisis di B/S2, berakhir
dengan `The read operation timed out`, tanpa status HTTP dari gateway.
Checkpoint mencatat tiga request generasi dan tiga analisis pada run tersebut;
dua respons analisis tersimpan sebelum timeout. Error transport menghentikan
batch sesuai protokol.

Setelah batch berhenti, satu pemeriksaan akses terpisah mengembalikan `API_OK`
dengan HTTP 200 dalam 1,704 detik. Alias yang diminta adalah
`Qwen3.8-27B`; gateway melaporkan `self-dploy/Qwen3.8-27B`. Ini memastikan
endpoint dapat melayani satu request kecil pada 12:25 WIB, tetapi belum
membuktikan kestabilan request analisis yang lebih berat.

Total executor adalah 732 request HTTP DVWA. Ledger mencatat 258 logical probe
submissions pada run yang memiliki agregat lengkap; agregat probe pada B/S2
tidak diketahui. Lima attempt yang dimulai masing-masing mencatat reset
database.

## Perbaikan duplikat

Pada A/S1, generator menghasilkan delapan kandidat yang dianalisis penuh.
Slot kesembilan ditolak tiga kali sebagai `no_valid_distinct_candidate`.
Loop selesai tanpa crash `KeyError: 'status'`; unit dicatat tidak eligible
karena hanya menghasilkan delapan dari sepuluh kandidat. B/S1 menghasilkan
sepuluh kandidat lengkap. Ini menunjukkan perbaikan penanganan duplikat aktif,
namun pilot belum cukup untuk menilai stabilitas pada keseluruhan skenario.

Belum ada penilaian manusia VAL-01 atas output pilot ini. Angka konfirmasi
executor bersifat deskriptif untuk pengembangan dan tidak digunakan sebagai
PSR atau FPR formal. Dataset hanya mencakup satu run LLM dan dua run SecLists
eligible, sehingga belum menjawab perbandingan A/B/C.

## Audit dan langkah berikutnya

Audit rekonsiliasi lulus. Hash 1.301 file data historis dan seluruh 32 source
runtime cocok dengan snapshot sebelum eksekusi. Source indeks pengetahuan juga
tetap utuh; retrieval kondisi B menggunakan salinan terverifikasi. Receipt
persetujuan, ledger, checkpoint dan request/response API disimpan terpisah.

P3 live masih belum selesai. Request kecil berhasil, sementara satu request
analisis sebelumnya timeout; perlu keputusan baru sebelum memulai attempt
atau run berikutnya. Budget v3 mengizinkan nol attempt pengganti otomatis;
pilot ini tidak dilanjutkan dari checkpoint timeout. Setelah pengumpulan yang
disetujui selesai, lakukan blind review VAL-01 pada bukti baru dan baru
kemudian hitung metrik yang relevan.
