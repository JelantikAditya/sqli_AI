## Perbaikan yang dibuktikan

- Timing menggunakan payload yang sama, dengan satu argumen literal `SLEEP`
  dalam rentang lebih dari nol sampai dua detik diganti menjadi nol. Bentuk
  SQL lainnya tetap sama. Baseline normal `id=1` tetap dipakai untuk memeriksa
  kesehatan target. Hash payload kontrol dan policy
  `same-payload-sleep-zero-v1` dicatat pada evidence.
- Selisih minimal 1500 ms hanya menjadi sinyal timing jika kandidat dan
  kontrol mengembalikan indikator blind yang valid dan sama. Respons syntax
  error atau generic HTTP error kandidat menjadi kandidat gagal, sedangkan
  hilangnya sesi atau baseline normal menjadi runtime invalid.
- DVWA Low/High mengembalikan HTTP 404 untuk kondisi `MISSING`. Respons itu
  diterima jika indikator `User ID is missing` ada. Generic 404/500 tetap
  gagal. Pilot awal yang menemukan aturan HTTP 200 terlalu ketat disimpan
  terpisah di `results/raw/pilot/t03-controls-20261014/`.
- Executor memeriksa action, method dan field injection pada form yang baru
  diambil. Medium memakai select POST; High memakai helper session/cookie
  lalu mengambil hasil modul. Impossible mengambil token baru setiap probe.
  Kesalahan sesi pada respons helper dihentikan sebelum hasil berikutnya.
- Baseline kini memiliki record sendiri pada semua teknik. Error memakai
  dua probe per konfirmasi; boolean dan timing masing-masing tiga. Satu
  pasangan boolean tetap dihitung sebagai satu kandidat logis.
- Runner memeriksa seluruh role probe tepat satu kali pada setiap konfirmasi
  dan mempertahankan konteks experiment/run/attempt/kandidat. Kegagalan tak
  terduga pada orchestrator dicatat sebagai attempt invalid, bukan dibiarkan
  dalam status running.
- Callback generator dua argumen tetap didukung pada loop adaptif. CLI
  memakai callback retry-aware agar prompt regenerasi menerima nomor retry
  tanpa menambah probe konfirmasi.

113 tes offline lulus, termasuk kontrol timing, token baru, Medium/High form,
respons helper yang kehilangan sesi, penolakan probe evidence tidak lengkap,
serta kompatibilitas feedback/regenerasi. Tes ini tidak mengirim request DVWA
atau melakukan inferensi Qwen.

## Reproduksi kontrol executor

Jalankan dari root repository dengan virtual environment dan DVWA lokal
aktif. Gunakan direktori output baru; pilot menolak overwrite. Perintah ini
melakukan 12 reset database sampel DVWA.

```powershell
.\.venv\Scripts\python.exe -B dvwa/run_executor_control_pilot.py --output-dir results/raw/pilot/t03-controls-new-run --confirm-local-dvwa --confirm-database-reset
```

Artefak penuh disimpan lokal pada `results/raw/pilot/<nama-run>/`: batch
manual, validation JSONL, log CLI per skenario, dan `pilot.summary.json`.

## T05: lifecycle budget generasi

Percobaan `t05-s1-abc-20261014` menghasilkan lima kandidat A yang valid,
lalu berhenti setelah batas regenerasi duplikat. Implementasi awal menandainya
runtime invalid dan menahan B/C. Protokol T01 sudah menetapkan incomplete
budget sebagai excluded dari metrik; masalah ini merupakan ketidaksesuaian
implementasi dan diperbaiki tanpa mengubah keputusan metode.

Runner sekarang mencatat attempt selesai dengan budget tidak lengkap sebagai
`metric_eligible=false` dan `run_excluded`, mempertahankan evidence serta klaim
setiap kandidat, lalu melanjutkan kondisi berikutnya dengan reset baru. Tidak
ada retry atau pemutihan hasil kondisi yang excluded. Gangguan sesi, baseline,
atau layanan model tetap runtime invalid dan memerlukan recovery. Konfigurasi
pilot baru ada di
[`../dvwa/local_run_plan.abc-s1-20261014-r2.json`](../dvwa/local_run_plan.abc-s1-20261014-r2.json).

118 tes offline lulus setelah perubahan ini. Kasus baru memeriksa budget
generasi sebagian/nol, outage layanan model, penghentian exception tak terduga,
dan kelanjutan kondisi berikutnya tanpa retry ketika kondisi awal excluded.

Pilot `t05-s1-abc2-20261014` membuktikan perilaku tersebut secara nyata:
A dan C masing-masing lengkap 10 kandidat; B memiliki 4 kandidat lalu
excluded ketika batas regenerasi duplikat habis. C tetap dieksekusi dengan
reset baru. Ketiganya mempunyai satu attempt, tanpa runtime invalid atau
retry lintas attempt. Execute-resume pada status akhir tidak mengubah hash
ledger atau menambah reset/probe. Evidence:
[`evidence/t05-abc-s1-lifecycle-live-2026-10-14.json`](evidence/t05-abc-s1-lifecycle-live-2026-10-14.json).

Pilot A/B/C ini belum memenuhi kesepadanan budget penuh karena B tidak lengkap.
Keragaman generasi B tetap menjadi masalah operasional untuk T02/T07; hasil
partial tidak boleh diganti dengan nol atau dipakai untuk menyimpulkan efek RAG.
